# DARKSTAR runtime contract

> [Documentation index](../../README.md)

**Status:** Proposed normative contract for `darkstar.local/v1alpha1`  
**Decision:** DS-008  
**Consumers:** daemon, CLI, dashboard, recovery workers, adapters, and tests

## 1. Decision

DARKSTAR exposes versioned resources and an append-only event log. Commands are
accepted once, append domain events under optimistic concurrency, update rebuildable
projections, and enqueue external work in one SQLite transaction. The HTTP API,
SSE feed, CLI, recovery logic, and tests observe that same contract; none treats a
provider transcript, UI view model, or process exit as domain state.

The public stability boundary is:

- resource identity and relationships;
- event envelope, ordering, and domain meanings;
- command idempotency and optimistic concurrency;
- projection rebuild semantics;
- HTTP resource/error/pagination/SSE behavior; and
- CLI exit and error-class mapping.

Storage indexes, internal worker messages, raw provider fixtures, and dashboard
layout are not public contracts.

## 2. IDs, time, and versions

Public IDs are opaque strings generated by DARKSTAR. They use a type prefix and a
26-character uppercase Crockford Base32 ULID payload, for example
`run_01K3Z1C1Y7A8V6R2W4M5N9Q0ST`. Valid prefixes are `project`, `work`, `run`,
`visit`, `attempt`, `artifact`, `approval`, `operation`, and `event`. Clients may
validate a prefix but must not parse time, sort, or infer relationships from IDs.

All timestamps are RFC 3339 UTC with fractional seconds. Business ordering uses
explicit positions and revisions, never wall-clock order. Event envelope version,
resource representation version, workflow version, and provider protocol version
are separate values.

The MVP API base is `/api/v1`. Additive response fields and event metadata are
compatible. Removing/renaming fields, changing enum meaning, or changing command
effects requires a new API or event schema version. Unknown event kinds are
retained and ignored by projections that do not understand them; a required event
schema version that a consumer cannot parse stops that consumer at a recorded
position.

## 3. Core resources

| Resource | Stable meaning | State authority |
|---|---|---|
| Project | repository/configuration boundary | project event stream |
| Work item | requested deliverable and owned delivery line | work event stream |
| Run | one pinned workflow execution for a work item | run event stream |
| Node visit | one activation of a workflow node and immutable input digest | run events/projection |
| Attempt | one bounded provider/validator execution for a visit | attempt event stream |
| Artifact | immutable evidence plus versioned representations | artifact event stream/store |
| Approval | one typed, scoped pending decision | approval event stream |
| Operation | durable intent/result for a side effect | operation event stream/outbox |
| Event | immutable fact at a global position | events table |

Provider thread/turn/item IDs live in an `external_refs` boundary keyed to an
attempt. Git SHAs and pull-request IDs live in work/operation evidence. Raw
provider events and UI-only state never appear in core resource payloads.

Every mutable resource representation has `id`, `resourceVersion` (aggregate
revision), `createdAt`, and `updatedAt`. HTTP ETags are the quoted decimal
`resourceVersion`.

## 4. Event contract

The machine-readable envelope is
[`runtime-event-v1alpha1.schema.json`](../../../schemas/runtime-event-v1alpha1.schema.json).
Required fields are:

```json
{
  "schemaVersion": 1,
  "id": "event_01K3Z1C1Y7A8V6R2W4M5N9Q0ST",
  "globalPosition": 42,
  "streamId": "run_01K3Z1C2AAAAAAAAAAAAAAAAAA",
  "streamSequence": 7,
  "aggregateType": "run",
  "aggregateId": "run_01K3Z1C2AAAAAAAAAAAAAAAAAA",
  "aggregateRevision": 7,
  "kind": "node_visit.completed",
  "occurredAt": "2026-08-31T00:00:02.000Z",
  "recordedAt": "2026-08-31T00:00:02.010Z",
  "correlationId": "run_01K3Z1C2AAAAAAAAAAAAAAAAAA",
  "causationId": "event_01K3Z1C1Y7A8V6R2W4M5N9Q0SR",
  "commandId": "cmd-complete-visit-1",
  "actor": {"type":"system","id":"daemon"},
  "data": {},
  "metadata": {}
}
```

`globalPosition` is a gap-free committed integer on one database. Stream sequence
and aggregate revision start at 1 and increase by exactly one. The MVP maps one
aggregate to one stream, so the two counters are equal. `occurredAt` describes the
fact; `recordedAt` is authoritative for persistence. `correlationId` follows the
run or originating request. `causationId` names the prior event, command, or null
root. Actor types are `user`, `system`, `provider`, and `external`; provider actor
identity is a registry key, not a raw protocol object.

Event `data` contains only domain facts required to rebuild state. `metadata` may
contain trace IDs, safe diagnostics, redaction markers, and external-reference
locators, but must not affect reducers. Secrets, raw prompts, provider payloads,
stack traces, and UI state are prohibited.

Initial domain kinds include project/work/run lifecycle; `node_visit.*`;
`attempt.*`; `artifact.*`; `approval.*`; `operation.*`; and `context.*`. Kind
semantics are append-only once published. Corrections append a compensating or
superseding event rather than editing history.

## 5. Commands, transactions, and recovery

Each mutating request supplies a caller-stable `Idempotency-Key`; commands against
an existing aggregate also supply `If-Match`. Within `BEGIN IMMEDIATE`, the daemon:

1. reads an existing command row by `(scope, idempotency_key)`;
2. returns the stored status/body if its request digest matches, or returns
   `IDEMPOTENCY_CONFLICT` if it differs;
3. compares expected and current aggregate revision;
4. validates policy and invariants;
5. inserts all events with consecutive positions/sequences;
6. updates projections and aggregate revision;
7. inserts outbox intents; and
8. stores the canonical command response before commit.

No network, process, filesystem, Git, or provider mutation occurs inside the
transaction. An outbox worker claims operations with a lease, records intent
before the external effect, and appends observation/result events in a later
transaction. Recovery follows DS-003 and never infers success from a dequeued row.

SQLite uses WAL, foreign keys, a bounded busy timeout, explicit transactions, and
one writer coordinator per database. Disk-full, corruption, or inability to sync
is fatal to new commands. Read projections may lag only when explicitly labeled;
command responses use the just-committed projection.

[`sqlite-v1alpha1.sql`](../../../schemas/sqlite-v1alpha1.sql) is the logical model.
Migrations are forward-only, transactional when SQLite permits, checksummed, and
recorded before a binary serves traffic. Event payloads retain their schema version
through migrations. Projections can be dropped and rebuilt from position zero;
events, commands, and external-effect evidence cannot.

## 6. HTTP API

[`openapi-v1alpha1.json`](../../../schemas/openapi-v1alpha1.json) defines the
initial loopback API. JSON uses UTF-8, rejects duplicate keys, and is limited by
request-specific byte/depth/item bounds. Authentication follows DS-009 and the
threat model. Mutation responses are `201` for creation, `200` for an idempotent
replay or transition, and `202` only when they expose a durable operation resource.

Errors use [`api-error-v1alpha1.schema.json`](../../../schemas/api-error-v1alpha1.schema.json)
and include stable `code`, safe `message`, `requestId`, retryability, optional
field details, and the current resource version where relevant. HTTP status alone
is never the programmatic error contract.

### Pagination

Collections use keyset pagination with `limit` (default 50, maximum 200) and an
opaque authenticated `after` cursor. The cursor freezes endpoint, filters,
ordering, last sort key/ID, and schema version. Default ordering is `(createdAt,
id)` ascending unless documented otherwise. A response has `items` and
`pageInfo:{nextCursor,hasNextPage}`. Inserts before the cursor do not duplicate
items; retention or filter mismatch returns `CURSOR_INVALID`, never silently
restarts at page one.

### SSE replay

`GET /api/v1/events` returns `text/event-stream`. Each domain event is one SSE
message with `id` equal to decimal `globalPosition`, `event` equal to `kind`, and
`data` equal to the complete JSON envelope. `Last-Event-ID` resumes strictly after
that committed position. Ordering is increasing and duplicates may occur across
reconnect, so clients deduplicate by event ID. Keepalives are comments and have no
position. The server closes slow consumers with an explicit final problem event.

If the requested position is older than retained online history, the server
returns `410 EVENT_REPLAY_UNAVAILABLE` with `oldestAvailablePosition` and a
projection resync link. The MVP retains the authoritative local event log; export
or compaction may change online retention only under a future explicit policy.

## 7. CLI mapping

The CLI prints user output to stdout, diagnostics to stderr, and supports a stable
JSON envelope. It maps API error codes, not message text:

| Exit | Meaning | Example codes |
|---:|---|---|
| 0 | command accepted/completed or read succeeded | — |
| 2 | CLI usage or local input invalid | `CLI_USAGE`, `INPUT_INVALID` |
| 3 | authentication/authorization/approval denied | `UNAUTHENTICATED`, `FORBIDDEN`, `APPROVAL_DENIED` |
| 4 | resource absent or precondition conflict | `NOT_FOUND`, `REVISION_CONFLICT`, `IDEMPOTENCY_CONFLICT` |
| 5 | dependency/capability unavailable | `PROVIDER_UNAVAILABLE`, `CAPABILITY_MISSING` |
| 6 | timeout/interruption/cancellation | `TIMEOUT`, `INTERRUPTED`, `CANCELLED` |
| 7 | policy or validation failure in requested work | `POLICY_DENIED`, `VALIDATION_FAILED` |
| 8 | daemon/storage/internal failure | `DAEMON_UNAVAILABLE`, `STORAGE_FAILURE`, `INTERNAL` |

Synchronous CLI waiting does not change command semantics. Ctrl-C sends one
idempotent cancellation command when safe and exits 6 after observing or timing
out; it never reports a cancelled remote operation as successful.

## 8. Fake end-to-end trace and acceptance

[`fake-run.json`](../../../examples/runtime/fake-run.json) represents creation,
context freeze, node/attempt execution, artifact creation, an approval checkpoint,
and run completion without UI or provider protocol state. The reference validator
checks positions, stream sequences, aggregate revisions, causation, idempotency,
and final projections.

The contract is accepted when:

- the fake trace validates and reconstructs its documented projections;
- a repeated command returns the same response without new events;
- a changed payload under the same key conflicts;
- SSE replay after any position yields the same ordered suffix;
- all schema references resolve and the initial OpenAPI surface uses versioned
  paths and shared errors; and
- no core event contains forbidden UI/provider protocol fields.
